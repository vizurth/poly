\section{Права пользователей}

\subsection{Постановка задачи}
В работе настроено разграничение доступа для двух пользователей базы данных.
Пользователь \textbf{А} может читать таблицу \texttt{car\_stats}, но не имеет
прав на исходные таблицы. Пользователь \textbf{Б} может читать и изменять
таблицы \texttt{car}, \texttt{alert\_event}, \texttt{parking\_session} и
\texttt{parking\_zone}, но не имеет прямого доступа к \texttt{car\_stats}.
Изменение статистики при работе с исходными таблицами выполняется ранее
созданными триггерами.

\subsection{Назначение прав доступа}
Пользователи созданы с правом подключения к базе данных и использования схемы
\texttt{public}. Пользователю А выдано право чтения таблицы статистики.
Пользователю Б выданы права чтения и изменения исходных таблиц, а также права
на использование последовательностей, формирующих идентификаторы. Чтобы
триггеры могли обновлять \texttt{car\_stats} от имени владельца функции,
функциям назначен режим \texttt{SECURITY DEFINER} и явно задана схема поиска.
SQL-команды настройки приведены в листинге~\ref{lst:user-privileges}.

\begin{lstlisting}[style=sqlstyle, caption={Создание пользователей и назначение прав}, label={lst:user-privileges}]
CREATE USER user_a WITH PASSWORD '123';
CREATE USER user_b WITH PASSWORD '123';

GRANT CONNECT ON DATABASE db TO user_a, user_b;
GRANT USAGE ON SCHEMA public TO user_a, user_b;

-- пользователь А читает только таблицу car_stats
GRANT SELECT ON car_stats TO user_a;

-- пользователь Б читает и изменяет исходные таблицы, но не имеет прямого доступа к car_stats
GRANT SELECT, INSERT, UPDATE, DELETE 
ON TABLE car, alert_event, parking_session, parking_zone
TO user_b;

-- для пользователя Б разрешаем автоинкрементные id
GRANT USAGE, SELECT ON SEQUENCE
	car_car_id_seq, 
	alert_event_alert_event_id_seq, 
	parking_session_parking_session_id_seq, 
	parking_zone_parking_zone_id_seq
TO user_b;

ALTER FUNCTION car_stats_change() SECURITY DEFINER  SET search_path = public;

ALTER FUNCTION alert_event_stats_change() SECURITY DEFINER SET search_path = public;

ALTER FUNCTION parking_session_stats_delete() SECURITY DEFINER SET search_path = public;
\end{lstlisting}

\subsection{Проверка прав пользователей}
Проверка выполнена в двух консольных сеансах, подключённых к одной базе данных:
в первом использовалась учётная запись пользователя А, во втором — пользователя
Б. Это позволило проверить, какие операции доступны каждой учётной записи, и
убедиться, что триггеры обновляют статистику при изменении исходных данных.

\paragraph{Чтение таблиц.}
Пользователь А выполнил запрос к \texttt{car\_stats} и получил строки со
статистикой автомобилей. Для пользователя Б такой же запрос завершился ошибкой. При этом пользователь Б смог
прочитать таблицу \texttt{car}. Результаты показаны на
рисунках~\ref{fig:access-before} и~\ref{fig:b_car}.

    \label{fig:access-before}
\end{figure}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.5\linewidth]{myPhoto/b_car.png}
    \caption{Пользователь Б читает таблицу car}
    \label{fig:b_car}

\paragraph{Добавление тревожного события.}
Попытка пользователя А добавить строку в \texttt{alert\_event} была отклонена из-за отсутствия права \texttt{INSERT}. Пользователь Б выполнил такую
вставку успешно. Этот результат приведён на рисунке~\ref{fig:insert_b}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{myPhoto/insert_b.png}
    \caption{Вставка в alert\_event запрещена пользователю А и разрешена пользователю Б}
    \label{fig:insert_b}
\end{figure}

Для проверки триггера была выполнена ещё одна вставка пользователем Б. В этом
сеансе команда вернула ID \texttt{414}. До вставки значение \texttt{alert\_count}
для автомобиля с ID 1 составляло 5, после вставки оно стало равно 6. Пользователь
Б при этом не смог прочитать \texttt{car\_stats}, а пользователь А
увидел обновлённое значение счётчика. Результат показан на
рисунке~\ref{fig:step-3}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{myPhoto/step-3.png}
    \caption{После вставки тревожного события счётчик изменился с 5 до 6; прямое чтение car\_stats пользователю Б недоступно}
    \label{fig:step-3}
\end{figure}

\paragraph{Удаление тревожного события.}
Пользователь А попытался удалить событие с ID \texttt{414}, но СУБД отказала
из-за отсутствия права \texttt{DELETE}. Пользователь Б удалил эту запись
успешно. После удаления значение
\texttt{alert\_count}, отображаемое пользователю А, изменилось с 6 на 5.
Результат приведён на рисунке~\ref{fig:step-4}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.7\linewidth]{myPhoto/step-4.png}
    \caption{Пользователю А запрещено удалять событие; пользователь Б удалил запись \texttt{alert\_event}}
    \label{fig:step-4}
\end{figure}

\paragraph{Обращение к таблице без выданных прав.}
Пользователи А и Б выполнили запрос к \texttt{alert\_event\_type}. Поскольку
право чтения этой таблицы не выдавалось ни одной учётной записи, обе попытки
завершились сообщением \texttt{permission denied}. Результат показан на
рисунке~\ref{fig:step-5}.
